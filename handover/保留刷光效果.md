# 保留刷光效果 keep_lighting_effect 交接文档

## 1. 概述

`keep_lighting_effect` 是灯光特效（Light Effect）系统中的一个布尔属性，用于控制**特效结束后无人机的颜色状态**。开启后，即使特效的影响范围或时间已过，无人机仍会保持之前被特效影响时的颜色。

## 3. 核心逻辑

### 3.1 执行流程概览

```
特效应用于颜色 (apply_on_colors)
    ↓
┌─ 第一帧 (frame_start):
│  清空 history，初始化当前帧历史
│
├─ 后续帧:
│  ┌─ keep_lighting_effect = False:
│  │  不执行任何历史逻辑
│  │
│  └─ keep_lighting_effect = True:
│     1. 检查前一帧历史是否存在
│     2. 如果缺失，向前遍历补全历史（逐帧跳转计算）
│     3. 复制前一帧历史到当前帧
│
├─ 颜色计算完成后:
│  ┌─ keep_lighting_effect = True:
│  │  如果无人机被特效影响 → 记录颜色到 history
│  │  如果未被影响但在 history 中 → 恢复历史颜色
│
└─ 颜色混合 (blend_in_place)
```

### 3.2 历史补全逻辑 [`apply_on_colors` 第825-830行](file:///e:/hhang/studio-blender/src/modules/sbstudio/plugin/model/light_effects.py#L825-L830)

```python
elif self.keep_lighting_effect:
    if frame - 1 not in self.history:
        for f in range(self.frame_start, frame + 1):
            bpy.context.scene.frame_set(f) if f not in self.history else None
        return
    self.history[frame] = copy.deepcopy(self.history[frame - 1])
```

**工作原理**:
1. 如果前一帧的历史不存在（例如用户跳帧播放），从 `frame_start` 逐帧跳转到当前帧，补全所有中间帧的历史
2. 如果历史完整，直接复制前一帧的历史作为当前帧的初始状态

**性能考虑**: 补全逻辑需要逐帧调用 `frame_set()`，在大量跳帧时可能导致性能下降。

### 3.3 颜色记录与恢复 [`apply_on_colors` 第949-953行](file:///e:/hhang/studio-blender/src/modules/sbstudio/plugin/model/light_effects.py#L949-L953)

```python
if self.keep_lighting_effect:
    if effected:
        self.history[frame][ids[index]] = new_color.copy()
    elif ids[index] in self.history[frame]:
        new_color = self.history[frame][ids[index]].copy()
```

**逻辑说明**:

| 条件 | 行为 | 说明 |
|------|------|------|
| `effected = True` | 记录颜色 | 无人机在特效影响范围内，将计算出的新颜色存入历史 |
| `effected = False` 且在历史中 | 恢复颜色 | 无人机不在影响范围内，但从历史中恢复之前被影响的颜色 |
| `effected = False` 且不在历史中 | 不处理 | 无人机从未被特效影响，使用原始颜色 |

## 4. History 数据结构

### 4.1 结构定义

```python
history = {
    frame_number: {
        drone_id: [r, g, b, a],  # RGBA 颜色
        ...
    },
    ...
}
```

**示例**:
```python
self.history = {
    1: {
        101: [1.0, 0.0, 0.0, 0.8],  # 无人机101在第1帧的颜色
        102: [0.0, 1.0, 0.0, 0.8],
    },
    2: {
        101: [1.0, 0.2, 0.0, 0.9],
        102: [0.0, 1.0, 0.2, 0.9],
    },
}
```

### 4.2 生命周期

| 阶段 | 操作 |
|------|------|
| 特效开始帧 | `self.history.clear()`，初始化 `{frame_start: {}}` |
| 特效进行中 | 逐帧复制前一帧历史，记录/恢复颜色 |
| 特效结束 | 历史保留，但不再更新 |
| 特效复制 | `self.history = copy.deepcopy(other.history)` |

## 5. 实际应用场景

### 5.1 场景一：区域灯光秀

**需求**: 无人机飞入某个区域时变为红色，飞出后保持红色。

| 配置 | 值 |
|------|-----|
| `target` | INSIDE_MESH |
| `mesh` | 区域边界网格 |
| `keep_lighting_effect` | True |
| `color_ramp` | 全红 |

**效果**:
- 无人机进入区域 → 变为红色
- 无人机离开区域 → **仍保持红色**（从历史恢复）
- 未进入过区域的无人机 → 保持原始颜色

### 5.2 场景二：时间衰减特效

**需求**: 特效结束后，无人机颜色不恢复到原始状态。

| 配置 | 值 |
|------|-----|
| `frame_start` | 100 |
| `duration` | 50 |
| `keep_lighting_effect` | True |

**效果**:
- 第100-149帧：特效正常应用
- 第150帧及以后：无人机保持第149帧的颜色

## 6. 与相关属性的交互

### 6.1 与 `influence` 的关系

`influence` 控制特效强度，`keep_lighting_effect` 在此基础上记录最终颜色：

```python
effected, influence = self._evaluate_influence_at(position, frame, condition)
alpha = max(min(influence, 1.0), 0.0)
new_color[3] *= alpha  # alpha 影响颜色透明度

if self.keep_lighting_effect:
    if effected:
        self.history[frame][ids[index]] = new_color.copy()
```

即使 `influence < 1.0`，只要 `effected = True`，颜色就会被记录。

### 6.2 与 `fade_in_duration` / `fade_out_duration` 的关系

淡入/淡出影响 `influence` 值，进而影响颜色的 alpha 通道。`keep_lighting_effect` 记录的是包含 alpha 的完整颜色。

### 6.3 与 `target` 的关系

| target | keep_lighting_effect 效果 |
|--------|--------------------------|
| ALL | 所有无人机都会被记录和保持颜色 |
| INSIDE_MESH | 只有进入网格的无人机被记录，离开后保持颜色 |
| FRONT_SIDE | 只有在平面前方的无人机被记录，移动到后方后保持颜色 |

### 6.4 与 `invert_target` 的关系

`invert_target = True` 时，目标条件取反。历史记录逻辑不变，只是 `effected` 的判定条件相反。

## 7. 数据结构

### 7.1 在 `update_from` 中的复制

```python
self.keep_lighting_effect = other.keep_lighting_effect
self.history = copy.deepcopy(other.history)
```

特效复制时，历史数据也被深拷贝。

### 7.2 在 `as_dict` 中的序列化

注意：`history` 和 `keep_lighting_effect` **不会被序列化**到字典中：

```python
def as_dict(self):
    return {
        "enabled": self.enabled,
        # ... 其他属性
        # 注意：history 和 keep_lighting_effect 不在此处
    }
```

这意味着特效导出时不会包含历史状态。

## 10. 常见问题 FAQ

### Q1: 什么时候应该开启 keep_lighting_effect？

当需要特效效果持久化时使用，例如：
- 无人机进入某个区域后永久变色
- 特效结束后保持最终颜色
- 需要记录历史颜色状态用于其他逻辑

### Q2: 开启后会影响性能吗？

会有一定影响：
1. 需要维护 `history` 字典，占用额外内存
2. 跳帧播放时会触发历史补全，逐帧调用 `frame_set()`
3. 每帧需要深拷贝历史数据

对于大规模无人机（>500）和长时间特效，建议关闭此选项。

### Q3: 历史数据会被清除吗？

仅在特效开始帧（`frame_start`）清空。特效结束后，历史数据保留但不再更新。

### Q4: 如果关闭此选项会怎样？

关闭后，特效仅在当前帧影响颜色。特效结束后，无人机会恢复到原始颜色（或其他特效的影响）。

### Q5: 历史记录的 key 是什么？

使用无人机 ID（`ids[index]`），而非索引。这是因为不同帧的无人机列表可能不同，ID 能确保准确对应。

### Q6: 可以手动访问历史数据吗？

可以，通过 Python 控制台：
```python
effect = bpy.context.scene.skybrush.light_effects.active_entry
print(effect.history)
# 获取特定帧特定无人机的颜色
color = effect.history[frame_number][drone_id]
```
